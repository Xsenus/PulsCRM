# Ручной smoke-test PulsCRM

Документ нужен для быстрой проверки после локального запуска, IIS deploy или восстановления из backup. Чеклист не заменяет автотесты, но фиксирует минимальный набор ручных действий, который подтверждает, что CRM открывается, API работает с нужной SQL Server БД, а рассылки можно подготовить и отправить.

## Перед началом

Заполните фактические значения для текущего стенда:

| Параметр | Значение |
| --- | --- |
| Дата проверки |  |
| Проверяющий |  |
| Frontend URL | `http://192.168.0.16:8080` |
| API URL | `http://192.168.0.16:8081` |
| Healthcheck URL | `http://192.168.0.16:8081/health` |
| SQL Server | `SERVER2016` или локальный instance |
| База данных | `TestPulsBase` или рабочая legacy БД |
| Git commit |  |
| Результат |  |

Перед ручным проходом желательно выполнить автоматические проверки:

```powershell
dotnet test backend\PulsNextMailing.sln --configuration Release --no-restore

Push-Location frontend\puls-next-web
npm test
npm run test:e2e
Pop-Location
```

Для production/IIS после деплоя дополнительно:

```powershell
.\scripts\smoke-iis.ps1 `
  -ApiBaseUrl http://localhost:8081 `
  -FrontendUrl http://localhost:8080

.\scripts\check-mailing-db.ps1 `
  -ConfigPath C:\PulsCRMConfig\Api\appsettings.Production.json `
  -RequireTransportProfile
```

## 8. Рассылки - отправка и очередь

Для безопасной автоматизированной проверки реальной отправки используйте локальный SMTP-catcher:

```powershell
.\scripts\smoke-mailing-e2e.ps1 `
  -ApiBaseUrl http://localhost:8081 `
  -Login "Администратор" `
  -Password "ВАШ_ПАРОЛЬ" `
  -RecipientEmail pulscrm-smoke@example.test `
  -SmtpPort 2525
```

Ручной UI-проход:

| Шаг | Действие | Ожидаемый результат | OK |
| --- | --- | --- | --- |
| 8.1 | Открыть сохраненную тестовую кампанию | Карточка кампании открывается без ошибок |  |
| 8.2 | Нажать ручной запуск | Создается dispatch batch, появляется success toast |  |
| 8.3 | Открыть статистику кампании | Счетчики очереди/отправки обновляются |  |
| 8.4 | Открыть `/dispatch` | Видны элементы очереди и партии отправки |  |
| 8.5 | Отфильтровать очередь по кампании | В списке остаются элементы нужной кампании |  |
| 8.6 | Проверить ошибочный элемент, если он есть | Видна причина ошибки и доступно повторное действие там, где оно допустимо |  |
| 8.7 | Повторно открыть список кампаний | Последние статусы и счетчики не ломают таблицу |  |

После проверки удалите временную кампанию и временный SMTP-профиль, если они создавались вручную. Автоматический `smoke-mailing-e2e.ps1` удаляет свои временные записи сам, если не указан `-KeepArtifacts`.

## 9. Адаптивность

Проверить страницы на ширинах 390px, 768px и 1366px:

| Страница | 390px | 768px | 1366px |
| --- | --- | --- | --- |
| `/login` |  |  |  |
| `/` |  |  |  |
| `/employees` |  |  |  |
| `/organizations` |  |  |  |
| `/campaigns` |  |  |  |
| `/campaigns/new` |  |  |  |
| `/settings` |  |  |  |
| `/dispatch` |  |  |  |

Критерии:

- нет горизонтального скролла страницы, кроме допустимого внутреннего скролла таблицы на desktop;
- текст не наезжает на кнопки, бейджи и соседние колонки;
- меню действий открываются внутри viewport;
- пагинация и выбор размера страницы доступны;
- формы можно заполнить с клавиатуры и на мобильном экране.
