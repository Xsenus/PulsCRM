# Статус roadmap PulsCRM

Дата актуализации: 2026-06-22.

Основа: `docs/project-roadmap.md`, `docs/project-analysis.md`, журнал `docs/whats-new.md`, автотесты и локальные DB/E2E smoke-проверки рассылок против SQL Server `ILYA\SQL2016 / PulsBaseDB`.

## Итог

Roadmap доведен до состояния MVP-ready, но формально не закрыт. Основные P0/P1-инкременты реализованы и регулярно проходят автоматические проверки, однако для окончательного закрытия нужен явный приемочный прогон ручного checklist и зафиксированное решение по релизу.

## Закрыто

- Основная база переведена на SQL Server, SQLite убран из runtime-сценария.
- Таблицы рассылок приведены к схеме `MailCampaign`, `MailDispatchItem` и другим `Mail*` сущностям.
- Фоновая обработка рассылок перенесена внутрь API.
- Для рассылок закрыт рабочий end-to-end контур: SMTP-профили, кампании, получатели, расписание, очередь, статистика, диагностика и локальный DB/E2E smoke.
- Для организаций закрыты ключевые UX-инкременты: декомпозиция карточки, вкладки, история, снимки, события, карточный мобильный режим и доступные переключатели.
- Для списков и таблиц закреплены единые паттерны `DataTable`, `RowActionsMenu`, `StatusBadge`, фильтры, card-mode и стабильные действия строк.
- Для адаптивности закрыта большая часть desktop/tablet/phone-полировки в ключевых разделах.
- Набор проверок расширен frontend unit-тестами, Playwright smoke-тестами, backend-тестами, сборками, audit/vulnerability scan и проверкой UTF-8 без BOM.
- IIS/autodeploy оформлены через self-hosted GitHub Actions runner, добавлены smoke, deploy, rollback и SQL-проверки.

## Частично закрыто

- Визуальная и accessibility-полировка доведена для основных экранов, но остается зоной текущих малых улучшений.
- Roadmap не преобразован в закрывающий checklist с отметками по каждому подпункту, поэтому исходный документ остается планом, а не актом приемки.
- Ручной checklist `docs/manual-smoke-test.md` есть, но финальный приемочный прогон и результат релизного решения не зафиксированы отдельной записью.
- Production/IIS post-deploy smoke описан и автоматизирован, но для формального закрытия нужен последний подтвержденный прогон на целевом окружении.
- P2/P3-улучшения считаются необязательными для MVP, но их нужно явно оставить в backlog или закрыть отдельным решением.

| 3. Организации | Закрыт для MVP | Карточка организации, вкладки, история, снимки и события доведены до рабочего адаптивного вида. |

## Что нужно для формального закрытия

1. Выполнить `docs/manual-smoke-test.md` на актуальной сборке и записать результат.
2. Подтвердить production/IIS smoke после деплоя или последней релизной сборки.
3. Зафиксировать решение по P2/P3: закрыть, перенести в backlog или исключить из MVP.
4. Добавить финальную запись в `docs/whats-new.md` о закрытии roadmap.
5. Сделать отдельный закрывающий коммит после приемки.

До выполнения этих пунктов корректная формулировка статуса: roadmap почти закрыт и готов к MVP-приемке, но не закрыт формально.
