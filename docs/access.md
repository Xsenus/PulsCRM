# Доступ к разделам

## Кто администратор

Администратор — сотрудник с галочкой **«Администратор системы»** в карточке сотрудника (`set_User.FlRoot`). Флаг проверяется по базе на каждый запрос к API, поэтому снятие или установка галочки действуют сразу, без повторного входа. Уволенный (группа «Уволенные») администратором не считается.

## Что видит каждый

| Раздел | Сотрудник | Администратор |
|---|---|---|
| Дашборд | приветствие, «Мои задачи» (открытые поручения мне и от меня), чат (непрочитанные и последние диалоги), дни рождения коллег на 2 недели с кнопкой «Поздравить», кто в сети, быстрые ссылки | то же + показатели рассылок и ссылки на разделы администрирования |
| Чат | да | да |
| Сотрудники | карточки коллег: фото, ФИО, должность, отдел, телефон, внутренний номер, e-mail, день рождения без года, «в сети», «Написать» | таблица с редактированием; переключатель «Таблица / Карточки» (выбор запоминается в браузере) |
| Организации | справочник только для чтения (`/directory/organizations`): поиск по названию, ИНН и району; карточка — реквизиты, адреса, телефоны, e-mail, руководитель, контактные лица. Без долгов, банковских реквизитов, комментариев, лицензий | полный раздел с редактированием (в карточке справочника — кнопка «Полная карточка») |
| Мой профиль | фото, телефоны, статус, пароль | то же |
| Аналитика, Рассылки, Очередь, Настройки | нет | да |

Сотрудник не видит этих пунктов в меню, а прямая ссылка на закрытый раздел открывает дашборд.

## Как это защищено на сервере

Скрытие в интерфейсе — только удобство; права проверяет API:

- политика `Admin` (`AccessPolicies.Admin`, `AdminAuthorizationHandler`) на контроллерах `analytics`, `campaigns`, `dashboard`, `diagnostics`, `dispatch`, `employees`, `files`, `organizations`, `transport-profiles`, `work` — не-администратору они отвечают `403`;
- для всех вошедших открыты `auth`, `chat`, `profile` (только свои данные), `my-work` (только свои поручения), справочник коллег `GET /api/colleagues`, `GET /api/colleagues/{id}`, `GET /api/colleagues/{id}/photo` и справочник организаций `GET /api/organization-directory`, `GET /api/organization-directory/{id}`. Справочник коллег отдает только рабочие контакты: без логина, прав, кода 1С, комментария и года рождения; уволенные в нем не показываются. Справочник организаций — только реквизиты и контакты (отдельный DTO, служебные поля в него не попадают).

Карточки ссылок в чате: на сотрудника — карточка коллеги (у всех); на организацию — у сотрудника из справочника организаций (клик открывает карточку справочника); на рассылку у сотрудника — «недоступно».

## Как добавить раздел

1. Пункт меню в `frontend/puls-next-web/src/components/AppShell.tsx` с `access: 'everyone'`, `access: 'admin'` или `access: 'employee'` (только в меню не-администраторов — когда у администратора есть полный раздел, как справочник организаций).
2. Маршрут в `src/app/App.tsx`: для всех — рядом с дашбордом и чатом, для администраторов — внутри `<Route element={<RequireAccess level="admin" />}>`.
3. Контроллер API: `[Authorize]` для всех или `[Authorize(Policy = AccessPolicies.Admin)]` для администраторов. Если сотрудникам нужна часть данных администраторского раздела — отдельный узкий эндпоинт с безопасным набором полей (как `/api/colleagues` рядом с `/api/employees`).
4. Ссылку на раздел — в «Быстрые ссылки» дашборда (`QuickLinks` в `src/pages/DashboardPage.tsx`).
