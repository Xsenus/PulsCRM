# Чат сотрудников

Личная и групповая переписка сотрудников внутри Puls Next: сообщения, ответы, редактирование и удаление, реакции, вложения с предпросмотром изображений, «печатает», «в сети», отметки прочтения и оповещения со звуком.

- Данные чата хранятся в **отдельной базе PostgreSQL** (`ChatDb`), ORM — XPO, как в остальном проекте.
- Сотрудники и их имена берутся из legacy-БД (`set_User`). В чате видны и доступны только работающие сотрудники: уволенные (группа «Уволенные») не появляются в поиске, их нельзя добавить в группу, личные диалоги с ними скрываются из списка и счетчиков, а в группах они не показываются среди участников. История переписки остается в базе.
- События в реальном времени идут через SignalR-хаб `/hubs/chat`; если он недоступен, интерфейс работает и обновляет список диалогов раз в 30 секунд.
- Вложения лежат на диске в `Storage:RootPath`/`Chat:StoragePath` (по умолчанию `C:/PulsCRMData/chat`), в базе — только метаданные.
- Для больших изображений браузер перед загрузкой делает уменьшенную копию (до 720 px по длинной стороне, WebP или JPEG, не больше 512 КБ) и отправляет ее вместе с оригиналом. Лента показывает копию (`GET /api/chat/attachments/{id}?thumbnail=true`), оригинал качается только при открытии на весь экран и при скачивании. Копия лежит рядом с оригиналом (`<имя>.thumb.webp`) и удаляется вместе с ним. GIF и картинки меньше 150 КБ уходят без копии. Сервер принимает копию, только если по сигнатуре это JPEG, PNG или WebP; изображения, загруженные до появления копий, показываются как раньше — оригиналом.

**По умолчанию чат выключен.** Пока не заданы `Chat:Enabled=true` и строка `ConnectionStrings:ChatDb`, API работает как раньше, к PostgreSQL не обращается, эндпоинты `/api/chat/*` и хаб отвечают 404, а пункт «Чат» в меню скрыт.

## Включение на production

### 1. База и пользователь в PostgreSQL

PostgreSQL на том же сервере может быть закрыт снаружи — API подключается к нему по `localhost`. Готовый скрипт создает пользователя `pulschat` и базу `pulschat` (UTF8) и дает ему права на создание таблиц; его можно запускать повторно (тогда он только обновит пароль). Выполнить на сервере из каталога репозитория (или скопировав файл), под суперпользователем PostgreSQL:

```powershell
psql -U postgres -f scripts\sql\create-chat-database.sql
```

`psql` спросит пароль для нового пользователя — задайте длинный, **без символа `;`** (он ломает строку подключения). Если `psql` нет в `PATH`, он обычно лежит в `C:\Program Files\PostgreSQL\<версия>\bin\psql.exe`.

Проверить вход новым пользователем:

```powershell
psql -h localhost -U pulschat -d pulschat -c "select current_user"
```

Вручную то же самое (если удобнее): `CREATE ROLE pulschat LOGIN PASSWORD '…'; CREATE DATABASE pulschat OWNER pulschat ENCODING 'UTF8' TEMPLATE template0;`, затем в базе `pulschat` — `ALTER SCHEMA public OWNER TO pulschat;`.

### 2. Production-конфиг API

В `C:\PulsCRMConfig\Api\appsettings.Production.json` (путь из переменной `API_CONFIG_PATH`) добавить строку подключения и секцию `Chat`:

```json
{
  "ConnectionStrings": {
    "ChatDb": "XpoProvider=Postgres;Server=localhost;Port=5432;User Id=pulschat;Password=ЗАМЕНИТЕ;Database=pulschat;Encoding=UNICODE"
  },
  "Chat": {
    "Enabled": true,
    "AutoCreateSchema": true
  }
}
```

- `Encoding=UNICODE` обязателен — без него кириллица и эмодзи могут сохраняться неверно.
- `AutoCreateSchema=true`: при первом обращении XPO создаст таблицы `ChatConversation`, `ChatParticipant`, `ChatMessage`, `ChatAttachment`, `ChatReaction`, `ChatUserSettings` и служебную `XPObjectType`, а после изменений моделей — допишет новые колонки. Колонки XPO не удаляет и не переименовывает. Например, колонки состояния плавающего окна (`DockOpen`, `DockConversationId`, `DockWidth`, `DockHeight` в `ChatUserSettings`) добавятся в уже созданную таблицу сами.
- Остальные настройки (значения по умолчанию):

| Параметр | По умолчанию | Что задает |
|---|---|---|
| `Chat:StoragePath` | `chat` | каталог вложений внутри `Storage:RootPath` |
| `Chat:MaxAttachmentBytes` | `26214400` (25 МБ) | максимальный размер одного файла |
| `Chat:MaxAttachmentsPerMessage` | `10` | файлов в одном сообщении |
| `Chat:MaxMessageLength` | `8000` | символов в сообщении |
| `Chat:MaxGroupMembers` | `200` | участников группового чата |
| `Chat:PendingAttachmentLifetimeHours` | `24` | через сколько часов удаляется загруженное, но не отправленное вложение (вместе с файлом) |
| `Chat:PendingAttachmentCleanupIntervalMinutes` | `360` | как часто запускается эта очистка |

Лимит размера запроса IIS (`maxAllowedContentLength` в `web.config` API, 200 МБ) больше лимита вложения — менять его не нужно.

### 3. WebSocket в IIS

Для мгновенной доставки нужен компонент IIS **WebSocket Protocol**:

```powershell
Install-WindowsFeature Web-WebSockets
```

После установки перезапустить пул `PulsCRM.Api` (или `iisreset`). Без компонента SignalR сам переключится на Server-Sent Events / long polling — чат будет работать, но с большей задержкой и нагрузкой.

Если перед API стоит другой reverse proxy, он должен пропускать `Upgrade`/`Connection` для `/hubs/` (пример — `frontend/puls-next-web/nginx.conf`).

### 4. Права на каталог вложений

Учетной записи пула `PulsCRM.Api` нужны права на запись в `Storage:RootPath` (каталог `chat` будет создан автоматически). Каталог вложений стоит включить в резервное копирование вместе с базой `pulschat`.

### 5. Применить

Новый конфиг подхватится при следующем деплое (workflow копирует `API_CONFIG_PATH`) или после ручного перезапуска пула `PulsCRM.Api`.

## Проверка после включения

1. `GET /api/chat/status` с токеном пользователя → `"enabled": true`.
2. В интерфейсе появился пункт «Чат»; в нем нет баннера «Нет связи с сервером чата».
3. В браузере (DevTools → Network → WS) есть соединение `/hubs/chat?id=...` со статусом `101`. Если вместо него запросы `eventsource`/`longPolling` — не установлен `Web-WebSockets`.
4. Два пользователя в разных браузерах: сообщение приходит сразу, у получателя звучит звук и всплывает оповещение, счетчик в меню растет и сбрасывается при прочтении, у отправителя появляется ✓✓.
5. Вложение-картинка показывает превью и открывается на весь экран; файл скачивается.
6. В PostgreSQL появились таблицы:

```sql
\c pulschat
\dt "Chat*"
```

После первого успешного запуска можно поставить `"AutoCreateSchema": false` — тогда API не будет менять схему; перед выкладкой версии с новыми полями моделей чата верните `true` или добавьте колонки вручную.

## Упоминания (@)

В групповом чате после «@» появляется список участников (поиск по любому слову имени или логину, ↑/↓ и Enter/Tab для выбора), в текст подставляется «@Имя Фамилия». Упомянутый сотрудник получает звук и оповещение **даже если диалог у него «без звука»** (общие настройки звука и оповещений при этом соблюдаются), упоминание подсвечивается в ленте, у диалога в списке появляется значок «@», а в общем счетчике непрочитанных диалог «без звука» учитывается только упоминаниями. Сервер засчитывает упоминание, только если сотрудник — действующий участник чата и его «@Имя» есть в тексте; если при правке имя убрали, упоминание снимается (новые при правке не добавляются).

## Пересылка сообщений

Меню «⋯» сообщения → «Переслать»: можно выбрать до 10 чатов сразу. В каждый уходит новое сообщение от имени пересылающего с пометкой «↪ Переслано от <автор>» и копиями файлов (копии живут отдельно: удаление оригинала их не затрагивает и наоборот, на диске это дополнительное место). При пересылке пересланного сохраняется автор оригинала. Переслать можно только из диалога, в котором сотрудник состоит, и только в свои диалоги; в личный диалог с уволенным — нельзя. API: `POST /api/chat/messages/{id}/forward` `{ conversationIds: [...] }`.

## Поиск по сообщениям

Строка поиска над списком диалогов (на странице «Чат» и в плавающем окне) ищет и по названиям чатов, и — от 2 символов — по тексту сообщений во всех диалогах сотрудника, включая архив; клик по найденному открывает диалог на этом сообщении (`/chat/{id}?message={messageId}`, более старая история догружается). Кнопка 🔍 в заголовке диалога ищет только в нем. Поиск без учета регистра, «ё» и «е» не различаются, удаленные и системные сообщения не ищутся, показываются последние 50 совпадений. API: `GET /api/chat/search?q=…&conversationId=…`.

## Закрепленное сообщение

В каждом диалоге можно закрепить одно сообщение (меню «⋯» → «Закрепить»): оно показывается плашкой над лентой у всех участников, клик по плашке прокручивает к нему (более старая история догружается сама). В личном диалоге закреплять может любой из двух собеседников, в групповом — владелец и администраторы. Новое закрепление заменяет прежнее; удаление закрепленного сообщения снимает закреп. Переход к сообщению по клику на цитату ответа теперь тоже догружает историю.

## Альбомы фото

В одно сообщение можно прикрепить до 10 файлов (`Chat:MaxAttachmentsPerMessage`): выбрать сразу несколько, перетащить или вставить из буфера. Пачка готовится и отправляется по 3 файла одновременно, по порядку выбора; полоса загрузки внизу не растет больше двух рядов. Несколько фото в сообщении показываются **альбомом-мозаикой**: по порядку, рядами по 1–3 фото во всю ширину, с учетом пропорций каждого (портреты уже, панорамы шире), с тонкими промежутками; клик открывает просмотр с листанием по всем фото альбома («4 из 10»). Файлы, не являющиеся картинками, идут списком под альбомом.

## Чтение, галочки и место в диалоге

- **Открытие на новых сообщениях.** Если в диалоге есть непрочитанные, он открывается на разделителе «Новые сообщения», а не внизу, даже если новых больше одной страницы (история догружается до первого непрочитанного, не больше 5000 сообщений). Новые сообщения, пришедшие, пока сотрудник читает выше, ленту вниз не утягивают: появляется кнопка «↓» с числом.
- **Прочтение по мере прокрутки.** Прочитанным отмечается то, что уже показано на экране, а не весь диалог сразу; счетчик непрочитанных уменьшается по мере чтения.
- **Галочки у своих сообщений:** одна серая — отправлено, две серые — доставлено (сообщение дошло до открытого браузера собеседника, даже если он его не открывал), две синие (на синем пузыре — голубые) — прочитано. В группе — хотя бы одним участником. Галочки видны и в списке диалогов, если последнее сообщение свое. Доставку браузер отмечает сам (`POST /api/chat/delivered`, пачкой раз в секунду); прочтение тоже означает доставку.
- **Место в диалоге.** Если сотрудник пролистал диалог наверх и ушел (в другой чат, на другую страницу, перезагрузил вкладку), при возврате диалог откроется там же. Долистал до конца — место забывается. Новые сообщения важнее запомненного места. Хранится в браузере (localStorage), на другом компьютере не переносится.

## Загрузка ленты и фото

- **Сообщения порциями.** При открытии диалога грузятся последние 50 сообщений (или больше — до первого непрочитанного/запомненного места). Старая история подгружается при прокрутке вверх заранее, когда до верха остается ~800 px, поэтому паузы на «Загрузка…» обычно не видно. Для этого запроса в `ChatMessage` есть составной индекс `(Conversation, OID)` — его создает XPO.
- **Сначала текст, потом фото.** Текст и данные о вложениях приходят одним запросом; картинки качаются после, отдельно. Под каждое фото сразу резервируется место по пропорциям, поэтому лента не прыгает.
- **Размытое превью.** При загрузке браузер делает крошечную копию фото (до 24 px, ~1 КБ), она приходит вместе с сообщением — фото видно сразу (размыто), четкая уменьшенная копия проявляется поверх. Сервер принимает превью, только если это короткий data:URL WebP/JPEG с правильной сигнатурой. У фото, загруженных раньше, превью нет — для них серая заглушка.
- **Только то, что рядом с экраном.** Фото начинают грузиться за ~600 px до появления на экране; одновременно — не больше 4, сначала те, что видны сейчас; пролистанные мимо и еще не начатые загрузки отменяются. В ленте всегда уменьшенная копия, оригинал — только при открытии на весь экран (пока он грузится, показывается копия) и при скачивании. Загруженные картинки кэшируются браузером (до 150 в памяти вкладки, плюс HTTP-кэш на сутки).

## Черновики

Недописанное сообщение не теряется: оно остается в поле ввода при переходе в другой диалог, на другую страницу CRM и после перезагрузки, а в списке диалогов показывается как «Черновик: …». Черновики хранятся в браузере (localStorage) отдельно для каждого сотрудника и на сервер не уходят — на другом компьютере их не будет. Отправка сообщения очищает черновик, редактирование своего сообщения его не затирает. Черновики старше 30 дней забываются.

## Плавающее окно чата

На всех страницах, кроме самого раздела «Чат», справа внизу есть кнопка чата со счетчиком непрочитанных. Она открывает окно со списком диалогов и перепиской — писать, отвечать, ставить реакции и прикреплять файлы можно, не уходя с текущей страницы. Кнопки окна: «—» свернуть обратно в кнопку, «⤢» открыть этот диалог в разделе «Чат». Клик по всплывающему оповещению открывает диалог в этом окне. Размер окна меняется перетаскиванием левого или верхнего края и левого верхнего угла (от 320×380 до размера экрана); двойной клик по краю возвращает стандартный размер 390×600. Открыто ли окно, какой диалог в нем и его размер — хранится на сервере (в настройках чата пользователя), поэтому окно выглядит одинаково на всех компьютерах сотрудника. Браузер держит локальную копию, чтобы окно не мигало при загрузке; если сохранение на сервер не успело пройти (например, страницу сразу перезагрузили), при следующей загрузке берется локальное состояние и досылается на сервер. На телефоне окно разворачивается на весь экран.

## Связь с CRM

- **«Написать»** — в карточке сотрудника и в меню действий списка сотрудников: открывает (или создает) личный диалог с ним в плавающем окне, не уходя со страницы. Для себя и для уволенных сотрудников кнопки нет.
- **Карточки ссылок.** Если в сообщении есть ссылка на организацию, рассылку или сотрудника этой же CRM (например, скопированная из адресной строки `…/organizations/42/edit`), под текстом показывается карточка с названием (для организации — ИНН и район). Клик по карточке или ссылке открывает объект внутри приложения. Ссылки на другие сайты открываются как обычно, в новой вкладке. Если объект удален или недоступен пользователю, карточка так и пишет.

## Оповещения и звук

- Оповещение со звуком появляется, когда сообщение пришло не в открытый сейчас диалог (на странице «Чат» или в плавающем окне) или вкладка скрыта. Клик по оповещению открывает диалог.
- Диалоги с режимом «Без звука» не звучат, не показывают оповещения и не входят в общий счетчик в меню.
- Каждый пользователь настраивает сам (кнопка 🔔 в чате): оповещения вкл/выкл, показ текста сообщения, звук (5 вариантов) и громкость. Настройки хранятся на сервере.
- **Системные оповещения Windows** (уведомление в углу экрана, когда вкладка свернута или в фоне) включаются там же отдельной галочкой: браузер спросит разрешение. Они без звука — звук чат проигрывает сам; клик возвращает во вкладку и открывает диалог. Новое сообщение в том же диалоге заменяет предыдущее уведомление, а не копит стопку. **Работают только если CRM открыта по HTTPS (или на `localhost`)**: на адресе вида `http://192.168.0.16:8080` браузер их не дает, и в настройках об этом написано — оповещения внутри системы и звук при этом работают. Чтобы включить, нужен HTTPS-адрес для сайта (сертификат на IIS).
- Звук синтезируется браузером (Web Audio). Браузеры разрешают звук только после первого действия пользователя на странице — до первого клика оповещения будут без звука.

## Права в групповых чатах

| Действие | Участник | Администратор | Создатель |
|---|:---:|:---:|:---:|
| Писать, отвечать, ставить реакции | ✓ | ✓ | ✓ |
| Редактировать и удалять свои сообщения | ✓ | ✓ | ✓ |
| Удалять чужие сообщения | | ✓ | ✓ |
| Менять название, описание, иконку | | ✓ | ✓ |
| Добавлять участников, исключать участников | | ✓ | ✓ |
| Исключать администраторов, назначать администраторов | | | ✓ |

Если создатель выходит из чата или увольняется, владельцем становится старейший работающий администратор, а если администраторов нет — старейший участник; в чате появляется системное сообщение об этом. Когда из группы выходят все, она удаляется. В личном диалоге удалять можно только свои сообщения; выйти из него нельзя — его можно убрать в архив, он вернется при новом сообщении.

## Типовые проблемы

| Симптом | Причина и решение |
|---|---|
| Пункта «Чат» нет в меню | Не задан `Chat:Enabled=true` или строка `ChatDb` в production-конфиге; проверьте `GET /api/chat/status`. |
| `/api/chat/*` отвечает 500 «Unable to open database» | Неверная строка `ChatDb`, PostgreSQL не запущен или пароль не тот. Проверьте подключение: `psql -h localhost -U pulschat -d pulschat`. |
| Ошибка «permission denied for schema public» при первом запуске | У пользователя нет прав на создание таблиц: сделайте его владельцем базы (`ALTER DATABASE pulschat OWNER TO pulschat;`) или выдайте `GRANT CREATE ON SCHEMA public TO pulschat;`. |
| Баннер «Нет связи с сервером чата» | Хаб `/hubs/chat` недоступен: проверьте, что запрос `/hubs/chat/negotiate` не блокируется прокси/CORS (`Cors:Origins` должен содержать адрес фронтенда). |
| Сообщения приходят с задержкой в несколько секунд | Не установлен `Web-WebSockets` — SignalR работает через long polling. |
| Вложение не скачивается (404) | Файл удален с диска или изменился `Storage:RootPath`/`Chat:StoragePath`. |
| Кириллица в сообщениях превращается в «?» | В строке `ChatDb` нет `Encoding=UNICODE` или база создана не в UTF8. |
