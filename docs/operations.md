# Эксплуатация

## Журнал API

API пишет журнал в файлы: каталог `logs` внутри `Storage:RootPath` (по умолчанию `C:/PulsCRMData/logs`), один файл на день — `api-yyyyMMdd.log`, хранятся 30 дней (старые удаляются автоматически). Уровень — `Information` и выше; изменить: `"Logging": { "File": { "MinLevel": "Warning" } }`. Фильтры категорий из `Logging:LogLevel` действуют и на файл.

Учетной записи пула `PulsCRM.Api` нужно право записи в `Storage:RootPath` (как и для вложений).

Пользователь при внутренней ошибке видит «Сообщите администратору код: …» — по этому коду ошибка находится в журнале (строка `Необработанная ошибка запроса <код>`).

## Страница «Состояние системы»

Меню → «Состояние системы» (только администраторам), адрес `/system`:

- проверки: база Пульса и база рассылок (SQL Server), база чата (PostgreSQL, кодировка), место на диске (внимание — меньше 5 ГБ, ошибка — меньше 1 ГБ), запись в каталог ключей, **последняя резервная копия** (внимание — нет копий или старше 36 часов, ошибка — последний запуск скрипта с ошибкой; папка — `Backup:Root`, по умолчанию `C:\PulsCRMBackups`, см. `backup.md`), ключ подписи входа, ошибки за сутки;
- очередь рассылок, отправлено и ошибок за 24 часа, число браузеров с подпиской на уведомления, свободное место;
- размер файлов на сервере: вложения чата, файлы рассылок, журнал;
- последние 50 предупреждений и ошибок с подробностями (по клику);
- файлы журнала за 30 дней — скачать.

API: `GET /api/diagnostics/status`, `GET /api/diagnostics/logs/api-yyyyMMdd.log` (политика `Admin`).
