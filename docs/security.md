# Безопасность

## Ключ подписи входа (JWT)

Токены входа подписываются ключом `Jwt:SigningKey`. Если в конфиге он не задан, короче 32 символов или это заглушка из примеров (`REPLACE_WITH…`, `CHANGE_ME…`), API **само создает случайный ключ** и хранит его в каталоге ключей: `Storage:RootPath/Storage:KeysPath/jwt-signing-key.txt` (по умолчанию `C:/PulsCRMData/keys`), рядом с ключами Data Protection. При запуске в журнал пишется предупреждение.

- Файл ключа не удаляйте и не публикуйте: по нему можно выпустить токен любого сотрудника. При удалении создастся новый ключ, и всем придется войти заново.
- Свой ключ: впишите в `Jwt:SigningKey` случайную строку от 32 символов, например результат PowerShell
  `[Convert]::ToBase64String((1..64 | ForEach-Object { Get-Random -Maximum 256 }) -as [byte[]])`.
- Смена ключа (в том числе переход с заглушки на сгенерированный ключ при первой выкладке) — всем сотрудникам один раз войти заново.

## Защита от подбора пароля

- После **5 неудачных попыток за 15 минут** для пары «логин + адрес компьютера» вход закрывается на **15 минут** (сообщение «Слишком много неудачных попыток входа…»). С другого компьютера сотрудник войти может — чужие попытки его не блокируют. Удачный вход сбрасывает счетчик.
- Не больше **20 попыток входа в минуту** с одного адреса (ответ `429`).
- Счетчики хранятся в памяти API и сбрасываются при перезапуске пула.
- Пароли хранятся в legacy-формате (`set_User.Password`, MD5) — его использует настольный Пульс, поэтому сменить алгоритм нельзя без доработки Пульса.

## Ошибки сервера

Пользователь видит текст проверок (неверный пароль, «уже отправленное сообщение нельзя отменить» и т. п.). Для внутренних ошибок (SQL, сеть, ошибки кода) — «Внутренняя ошибка сервера. Сообщите администратору код: …»; по этому коду ошибка с подробностями записана в журнал API.

## Заголовки безопасности

- Сайт (`frontend/puls-next-web/public/web.config`): `X-Frame-Options: SAMEORIGIN` (CRM нельзя встроить в чужой сайт), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (камера и геолокация выключены, микрофон — только самой CRM).
- API: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`.

## Описание API (Swagger)

На production Swagger выключен: полный список методов не виден в сети. Включить временно: `"Swagger": { "Enabled": true }` в `appsettings.Production.json` и перезапуск пула. В режиме разработки Swagger доступен всегда (`http://localhost:5185/swagger`).

## HTTPS

Пока CRM работает по `http://`, пароли и переписка идут по сети открытым текстом. Рекомендуется внутренний сертификат на IIS (корневой сертификат — на компьютеры через групповую политику): тогда же системные уведомления чата заработают без дополнительной настройки браузера (см. `chat.md`).
